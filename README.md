# ares-gameserver

A [LostCity](https://github.com/LostCityRS) revision 274 game server and cache tooling in Rust. It packs the LostCity
Content repository into the cache the stock clients expect and speaks their wire protocol, so the stock clients and
Content work unchanged.

## Binaries

| binary | what it does |
|---|---|
| `ares` | The game world: the 600 ms tick loop, game port (TCP), and the web client with its WebSocket bridge. Packs the cache on first start if it is missing. |
| `ares-login` | Login server: accounts, sessions and player saves, backed by SQLite or MySQL. |
| `ares-friend` | Friend server: friends and ignore lists, private messages, cross-world presence. |
| `ares-logger` | Logger server: session and event logs written to the database. |
| `ares-pack` | Tooling: builds `data/pack` from Content and manages the login RSA key. |
| `ares-bots` | Load tester: logs in N mock players that walk and chat. |

`ares`, `ares-login`, `ares-friend` and `ares-logger` take the server root as an optional first argument (default:
the current directory). `ares-pack` always works on the current directory. `ares-bots` takes `--root`.

### `ares-pack` commands

```text
ares-pack build                 clean build of data/pack from build.srcDir
ares-pack clean                 remove data/pack and the regenerable .pack files
ares-pack symbols               data/symbols.json for the VS Code language server (dev mode writes it after every build)
ares-pack checksum              CRCs of the jags in data/unpack
ares-pack keygen                new data/config/{private,public}.pem (does NOT rebuild the client)
ares-pack rekey <Client-TS dir> new key compiled into a fresh web client build, then installed
ares-pack keycheck [--fix]      check private.pem, public.pem and public/client/client.js agree (--fix rewrites public.pem)
ares-pack import-npc-csv <file> rewrite map NPC spawns from a CSV
ares-pack import-obj-csv <file> rewrite map obj spawns from a CSV
```

### `ares-bots` options

```text
--host <addr>   game port (default 127.0.0.1:43594)
--root <dir>    server root, for data/pack CRCs and data/config/public.pem (default .)
--count <n>     bots (default 100)            --rate <n>    logins started per second (default 20)
--at <x,z>      gathering tile (default 3222,3218, Lumbridge)
--spread <n>    random offset per bot (default 0: one crowd)
--radius <n>    walk radius (default 8)       --chat <p>    chat chance per tick (default 0.02)
--secs <n>      run time (default: until Ctrl-C)
--prefix <s>    username prefix (default bot)
```

Bots use `::tele`, so the world must have `node.production` off. Every bot becomes a real account with a save file,
so point them at a throwaway server root, not a world you care about.

## The server root

Every binary runs against a server root directory. The `ares-gameserver` directory is one already:

```text
data/config/world.json     configuration (optional; every key has a default, see below)
data/config/private.pem    login RSA key (required)
data/config/public.pem     its public half (read by ares-bots and keycheck)
data/raw/wordenc           chat filter source (committed)
data/pack/                 the packed cache (generated by ares-pack build, or by ares on first start)
data/players/<profile>/    player saves
db.sqlite                  login/friend/logger database (when db.backend is sqlite)
public/                    the prebuilt web client (committed)
view/                      the web page templates (committed)
```

`build.srcDir` points at a [LostCity Content](https://github.com/LostCityRS) checkout (scripts, maps, models). It
defaults to `../content`, resolved against the server root.

## Running locally

Prerequisites: a Rust toolchain (edition 2024) and a Content checkout. Bun and git are only needed for
`ares-pack rekey`. The crate depends by path on [ares-compiler](https://github.com/sysdevs/ares-compiler) (the
script compiler) and [ares-shared](https://github.com/sysdevs/ares-shared) (the script ABI), so clone them next to
it:

```sh
git clone https://github.com/sysdevs/ares-shared
git clone https://github.com/sysdevs/ares-compiler
git clone https://github.com/sysdevs/ares-gameserver
```

1. Put Content next to `ares-gameserver`, or set `build.srcDir` (see the example below). On Linux the default `../content` is
   case-sensitive.
2. Provide the login key as `data/config/private.pem` and `public.pem`. The prebuilt `public/client/client.js` only
   accepts the key it was built with:
   - To keep the prebuilt client, use the key pair it was built with (the LostCity default key).
   - Or generate a new pair and rebuild the client with it in one step: `cargo run --release --bin ares-pack -- rekey ../Client-TS`.
   - `cargo run --release --bin ares-pack -- keycheck` confirms the three agree. `ares` also warns at startup if they
     do not.
3. Start the world:

   ```sh
   cargo run --release
   ```

   The first start packs the cache, which takes a while. Use `--release`: a debug build packs and ticks far slower.
   When the log says `World ready`, open `http://localhost/` (port 80 on Windows and macOS, 8888 on Linux; set
   `web.port` to change it).

With the defaults, the world runs on its own. `login.enabled` is off, so the world saves players to
`data/players/main/*.sav` itself and accepts any username and password. `node.production` is off, so every player is
staff level 4 and can use `::` commands. `build.liveReload` is on, so edits under Content rebuild the pack and reload
scripts and configs in place.

Useful in-game commands in development:

| command | effect |
|---|---|
| `::serverstats` | scroll with per-phase tick timings, player/NPC counts and bandwidth, refreshed every tick (close it, walk away, or repeat the command to stop) |
| `::reload` / `::rebuild` | reload the current pack / rebuild it from Content and reload |
| `::tele 0,50,50,10,10` | teleport (level, square x, square z, local x, local z) |
| `::~<name>` | run `[debugproc,<name>]` from Content |

To try the full multi-process setup locally, set `easyStartup`, `login.enabled` and `friend.enabled` (see Production),
and build every binary first with `cargo build --release --bins`, since `cargo run` builds only `ares`.

Cargo features: `web-client` (on by default) serves the web client. Build with `--no-default-features` for a
game-port-only server without the HTTP stack.

## Running in production

### Build

```sh
cargo build --release --bins
```

Copy `target/release/{ares,ares-login,ares-friend,ares-logger,ares-pack}` together with the server root (`data/`,
`public/`, `view/`) and the Content checkout to the host. Pack once on the host, or ship a `data/pack` built from the
same Content:

```sh
cd /srv/ares && ./ares-pack build
```

### Configure

A production `data/config/world.json`:

```json
{
  "easyStartup": true,
  "node": { "id": 10, "production": true, "debug": false, "members": true, "maxConnected": 2000 },
  "web": { "port": 8888, "allowedOrigin": "https://play.example.com" },
  "login": { "enabled": true, "host": "localhost", "port": 43500 },
  "friend": { "enabled": true, "host": "localhost", "port": 45099 },
  "logger": { "enabled": true, "host": "localhost", "port": 43501 },
  "db": { "backend": "mysql", "host": "localhost", "port": 3306, "user": "lostcity", "pass": "change-me", "name": "lostcity" },
  "website": { "registration": true },
  "build": { "srcDir": "/srv/content", "liveReload": false }
}
```

| key | default | notes |
|---|---|---|
| `node.production` | `false` | `true` turns off developer `::` commands and debugprocs, and staff levels come from the database |
| `node.debug` | `true` | `false` turns off the map editor routes (`/maped`, `/content/*`, `/data/*`) |
| `node.port` | `43594` | game port for TCP clients |
| `node.maxConnected` | `1000` | total player cap (the world holds at most 2047) |
| `node.id`, `node.members`, `node.xpRate` | `10`, `true`, `1` | world number, members world, XP multiplier |
| `web.port` | `80` (Windows/macOS), `8888` | HTTP and WebSocket port of the web client |
| `web.allowedOrigin` | `""` | when set, WebSocket game connections from other origins are refused |
| `login`, `friend` | disabled | `enabled`, `host`, `port` of each server |
| `logger.port` | `43501` | port `ares-logger` listens on (the world does not connect to it yet) |
| `easyStartup` | `false` | `ares` spawns the three servers from its own directory and stops them on exit |
| `db.backend` | `sqlite` | `sqlite` (`db.sqlite` in the root) or `mysql` (`host`, `port`, `user`, `pass`, `name`) |
| `website.registration` | `true` | `true` creates an account on first login; `false` only admits existing accounts |
| `build.srcDir` | `../content` | Content checkout |
| `build.liveReload` | `true` | rebuild and reload on Content changes (ignored when `production` is on) |

### Database

The login, friend and logger servers create and migrate the schema on startup (`migrations/sqlite` or
`migrations/mysql`). For MySQL, create the empty database and user first. An existing LostCity database is used as
is.

Staff levels live in the database: `UPDATE account SET staffmodlevel = 4 WHERE username = 'you';` (2 moderator,
3 admin, 4 developer).

### Processes

With `easyStartup`, run only `ares`. It starts `ares-login`, `ares-friend` and `ares-logger` from its own directory,
and they exit when it does, even if it is killed. Without `easyStartup`, start the three servers first, then `ares`,
each with the server root as its argument. Under systemd, give each its own unit with `WorkingDirectory=` set to the
server root, and order `ares` after the others.

Shutdown: Ctrl-C (SIGINT) on `ares` starts the in-game reboot timer at zero. Players are logged out and saved through
the login server before the process exits.

### Login key

Never run a public server on the key the stock client ships with, because its private half is public. Generate your
own key and the matching client build in one step, then restart:

```sh
./ares-pack rekey /srv/Client-TS     # clones Client-TS (branch = engine revision) if missing, needs git + bun
./ares-pack keycheck                 # private.pem, public.pem and public/client/client.js agree
```

`rekey` changes the server files only after the client built and was checked to carry the new key. Restart `ares`
afterwards, and tell players to hard-refresh, since browsers cache `client.js`.

### HTTPS and networking

`ares` serves plain HTTP and WebSocket. Put a reverse proxy (nginx, Caddy) in front for TLS, forwarding both normal
requests and WebSocket upgrades on `/` to `web.port`. Set `web.allowedOrigin` to the public origin. Client-TS has a
`SECURE_ORIGIN` build setting for serving over HTTPS (see its `bundle.ts`). Expose `node.port` only if you support
TCP clients. Keep the login, friend and logger ports private.

Back up `db.sqlite` (or the MySQL database) and `data/players/`.

### Load testing

On a staging copy of the server root (`production` off):

```sh
./ares-bots --host 127.0.0.1:43594 --root /srv/ares-staging --count 1000 --rate 100 --secs 300
```

While players are online, `ares` logs one line every 100 ticks with player and NPC counts, cycle time (current,
average and max over the last 100 ticks) and bytes sent per tick. As a reference point, 1000 bots crowded into
Lumbridge averaged about 20 ms per 600 ms tick on a desktop machine.

## Known gaps

- The world does not connect to the logger server yet, so no session logs, wealth events or input tracking are
  recorded. `ares-logger` runs and accepts them; `logger.enabled` and `logger.host` are unused.
- No `/setup` management page and no Prometheus metrics.

## Architecture

```
ares (main)                                   ares-login / ares-friend / ares-logger
 ├─ pack if data/pack is missing (in-process)   each: tokio + tokio-tungstenite server,
 ├─ easyStartup → spawn the three siblings       JSON text frames, sqlx (sqlite | mysql)
 ├─ World thread (600 ms tick loop)
 │    ├─ LoginLink { Ws | Inline }  ──JSON/WS──▶  ares-login
 │    └─ friend (optional WS)       ──JSON/WS──▶  ares-friend
 ├─ TCP game port (43594) → ClientId channels
 ├─ OnDemand task (cache streaming)
 ├─ dev hot-reload (notify → pack → dev_reload)
 └─ [feature web-client] HTTP: public/, /rs2.cgi, archive routes, WS game bridge
```

The World queues login and friend requests and gets replies back between ticks. With `login.enabled`, login requests go
to `ares-login` over a localhost WebSocket (`LoginLink::Ws`); otherwise `LoginLink::Inline` answers them in process and
saves to `data/players/<profile>/`, which the replay tests use too. The friend link exists only with `friend.enabled`.
One crate, six binaries; `src/lib.rs` has the module map.

## Development

Output is pinned by snapshot tests (`tests/differential.rs`): fixture content trees must pack to the committed cache
bytes, and recorded client sessions must replay to the committed wire bytes. Read `docs/behaviour.md` before changing
anything that reaches output bytes, and `docs/testing.md` for how the snapshots work.

```sh
cargo test --release                                                   # unit tests + snapshot gates
BLESS=1 cargo test --release --test differential full_build_matches     # after an intentional output change:
BLESS=1 cargo test --release --test differential                        #   rewrite snapshots, then review git diff
```
